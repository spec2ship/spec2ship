# Spec2Ship Workflow Guide

This guide explains the artifact flow, entry points, and traceability in s2s workflows.

## Artifact Flow Overview

```
                      ┌─────────────────────────┐
                      │   /s2s:brainstorm       │
                      │   OR manual entry       │
                      └───────────┬─────────────┘
                                  │
                                  ▼
                      ┌─────────────────────────┐
                      │      ideas.md           │
                      │      (IDEA-*)           │
                      └───────────┬─────────────┘
                                  │ promote
                                  ▼
┌──────────────────────────────────────────────────────────────┐
│                      BACKLOG.md                              │
│              (FEAT-*, BUG-*, TECH-*, DEBT-*)                 │
└──────────────────────┬───────────────────────────────────────┘
                       │
         ┌─────────────┼─────────────┐
         │             │             │
         ▼             ▼             ▼
┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│ /s2s:specs  │ │ /s2s:design │ │  /s2s:plan  │
└──────┬──────┘ └──────┬──────┘ └──────┬──────┘
       │               │               │
       ▼               ▼               ▼
┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│requirements │ │architecture │ │   plans/    │
│    .md      │ │    .md      │ │  {plan}.md  │
│ (REQ-*, NFR-*)│ │(COMP-*, ARCH-*)│ │             │
└─────────────┘ └─────────────┘ └─────────────┘
```

## File Structure

```
.s2s/
├── CONTEXT.md           # Project context (UPPERCASE - foundational)
├── BACKLOG.md           # Work items (UPPERCASE - foundational)
├── config.yaml          # Configuration
├── ideas.md             # Ideas (lowercase - generated by brainstorm)
├── requirements.md      # Requirements (lowercase - generated by specs)
├── architecture.md      # Architecture (lowercase - generated by design)
├── decisions/           # ADRs (ARCH-*)
├── sessions/            # Roundtable session files
└── plans/               # Implementation plans
```

### Naming Convention

| Case | Type | Examples |
|------|------|----------|
| UPPERCASE | Foundational files (human-maintained) | CONTEXT.md, BACKLOG.md |
| lowercase | Generated files (command output) | requirements.md, ideas.md, architecture.md |

## ID Conventions

| Prefix | Category | Source File | Status Values |
|--------|----------|-------------|---------------|
| IDEA | Ideas and concepts | ideas.md | draft, validated, promoted, parked, rejected |
| FEAT | Features | BACKLOG.md | draft, planned, in_progress, blocked, completed |
| BUG | Bug fixes | BACKLOG.md | draft, planned, in_progress, blocked, completed |
| TECH | Technical tasks | BACKLOG.md | draft, planned, in_progress, blocked, completed |
| DEBT | Technical debt | BACKLOG.md | draft, planned, in_progress, blocked, completed |
| REQ | Functional requirements | requirements.md | draft, in_progress, approved, rejected, deferred |
| NFR | Non-functional requirements | requirements.md | draft, in_progress, approved, rejected, deferred |
| COMP | Components | architecture.md | - |
| INT | Interfaces | architecture.md | - |
| ARCH | Architecture decisions | decisions/ | proposed, accepted, deprecated, superseded |

## Entry Points by Command

### /s2s:brainstorm

**Generates**: ideas.md (IDEA-*)

**Entry points**:
- Topic text (required)

**Output**: Ideas exported to .s2s/ideas.md with validation from Disney phases

---

### /s2s:specs

**Generates**: requirements.md (REQ-*, NFR-*, BR-*, EX-*)

**Entry points** (smart detection, no flags needed):
- Recent brainstorm sessions (auto-detected)
- Active ideas from ideas.md (auto-detected)
- Planned BACKLOG items (auto-detected)
- Specific ID: `specs IDEA-001` or `specs FEAT-002`
- Start fresh from CONTEXT.md only

**Example usage**:
```bash
/s2s:specs                    # Auto-detects available sources
/s2s:specs IDEA-001           # Use specific idea as input
/s2s:specs FEAT-003           # Use specific backlog item as input
```

---

### /s2s:design

**Generates**: architecture.md, decisions/ (ARCH-*)

**Entry points**:
- requirements.md (recommended, warns if missing)
- CONTEXT.md (basic mode)

---

### /s2s:plan

**Generates**: plans/{plan-id}.md

**Entry points** (smart detection, no flags needed):

| Input | Source | Action |
|-------|--------|--------|
| `plan FEAT-001` | BACKLOG.md | Read item, create plan |
| `plan REQ-003` | requirements.md | Read requirement, create plan |
| `plan COMP-002` | architecture.md | Read component, create plan |
| `plan IDEA-005` | ideas.md | **WARNING** + suggest specs first |
| `plan "user auth"` | Search all sources | Find best match |
| `plan` (empty) | BACKLOG.md | Show planned items to choose from |

**IDEA Warning**: Planning directly from ideas bypasses requirements validation. The command will warn and require explicit confirmation:

```
WARNING: Planning from unvalidated idea

You're trying to create a plan from IDEA-005: "OAuth integration"

Ideas should typically go through requirements validation first:
  1. /s2s:specs - Define and validate requirements
  2. /s2s:plan  - Then create implementation plan

Options:
- Run /s2s:specs first (recommended)
- Proceed anyway
- Cancel
```

## Traceability Links

Artifacts maintain bidirectional references:

### ideas.md → BACKLOG.md
```markdown
### IDEA-001: Feature Name
**Status**: promoted
**Promoted to**: FEAT-001
```

### BACKLOG.md → sources
```markdown
### FEAT-001: Feature Name
**Traceability**:
- **Originated from**: IDEA-001 | brainstorm:{session-id}
- **Implements**: REQ-001, REQ-002
- **Plan**: 20260119-143022-feature-name
```

### plans/ → sources
```markdown
## Traceability
**Source**: FEAT-001
**Source Type**: backlog
```

## Status Lifecycles

### Ideas (ideas.md)

```
draft ─────┬────────▶ validated ──┬──▶ promoted (→ BACKLOG)
           │                      │
           │                      └──▶ parked (deferred)
           │
           └─────────────────────────▶ rejected
```

### Backlog Items (BACKLOG.md)

```
draft ─▶ planned ─▶ in_progress ─▶ completed
                         │
                         └──▶ blocked ──▶ in_progress
```

### Requirements (requirements.md)

```
draft ─▶ in_progress ─┬──▶ approved
                      │
                      ├──▶ rejected
                      │
                      └──▶ deferred
```

## Recommended Workflows

### Complete Workflow (recommended)
```
/s2s:init           # Initialize project
    ↓
/s2s:brainstorm     # Explore ideas → ideas.md
    ↓
/s2s:specs          # Define requirements → requirements.md
    ↓
/s2s:design         # Design architecture → architecture.md
    ↓
/s2s:plan           # Create implementation plans → plans/
    ↓
implement           # Execute plans
    ↓
/s2s:plan:close     # Mark plan complete
```

### Quick Start (MVP mode)
```
/s2s:init           # Initialize project
    ↓
/s2s:plan "topic"   # Create plan directly
    ↓
implement           # Execute
```

### From Existing Ideas
```
/s2s:specs IDEA-001     # Define requirements from idea
    ↓
/s2s:plan FEAT-001      # Plan the promoted feature
```

## Coherence Checking

The LLM can verify artifact coherence on-demand:

- **Status sync**: Verify IDEA marked "promoted" has corresponding FEAT in BACKLOG
- **Traceability**: Verify plan references valid source IDs
- **Completeness**: Check all FEAT items have associated REQ-*

Run validation:
```bash
/s2s:session:validate
```
