## Purpose

5 unit-style assertions, one per strategy doc. For each strategy, freeze:
- The exact opening line of `## Strategy hooks` section (as it exists post Phase 7-lite).
- The regex anchor in `strategy-hook-resolution.md` that should match.
- The expected override dict produced by the parser.
- The expected Step 2.2c dispatch branch (1, 2, or 3).

Phase 4.5 step 2 (anchor parse fixture verification) runs the parser standalone against each strategy doc and asserts the output dict equals the expected dict frozen below. Any mismatch indicates either:
- A bug in the parser (regex doesn't match what it should), OR
- Drift in the strategy doc opening line (run the drift check script).

## Phase 4.5 step 2 verification procedure

For each of the 5 assertions:
1. Read the strategy doc (`skills/roundtable-strategies/references/{strategy}.md`).
2. Extract first non-empty line of `## Strategy hooks` section via `awk '/^## Strategy hooks/{flag=1;next} flag && NF{print; exit}'`.
3. Match against `matching_regex`; should succeed.
4. Look up the corresponding row in `strategy-hook-resolution.md` anchor table.
5. Verify produced dict equals `expected_dict`.
6. Verify Step 2.2c would dispatch via `expected_branch` (validate against `phase-2-core.md` Step 2.2c documentation).

Run order: independent per strategy; can be parallelized. All 5 must pass.

## Maintenance

If a strategy doc opening line legitimately changes (e.g. six-hats post-baseline transition from skip to policy dict), update this fixture file's assertion in lockstep with the strategy doc edit and the `strategy-hook-resolution.md` anchor table. Drift check script will catch desync.
