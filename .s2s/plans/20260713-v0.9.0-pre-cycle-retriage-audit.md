## 1. QUAL-001 — "Development tools are in the plugin but excluded from release"

**Verdict: the Context line was FALSE.** Nothing excluded them. Every packaging surface checked:

| Surface | State |
|---------|-------|
| `.claude-plugin/marketplace.json:11` | `"source": "./"` — the **whole repo tree is the plugin** |
| `.claude-plugin/plugin.json` | keys are exactly `name, version, description, author, repository, license, keywords` — no `files`, no `exclude`, no `ignore` |
| `.github/workflows/` | only `tests.yml` (runs `tests/run-all.sh`). No release job, no packaging job |
| `Makefile` | states explicitly that there is no build; targets are `test` and `hooks` |
| `.npmignore` / `.claudeignore` / release script | do not exist |

So `commands/dev/check.md`, `commands/dev/test.md`, `agents/dev/dev-validator.md` and `skills/dev-testing/**` — including the `dogfood-e2e.md` runbook — install into **every user's plugin**. The only "exclusion" is prose *inside* those files (`NOT SHIPPED - development only`), which excludes nothing: it is a comment, not a manifest.

The acceptance criterion "Tools NOT included in shipped plugin" was therefore never met, and had never been in progress. → filed as **BUG-027**.

**Second finding — RES-RT-\***: defined only. `agents/dev/dev-validator.md:25-30` accepts the categories `ENV, INST, CONS, VAL-RT, RES, EDGE` — **`RES-RT` is not among them** — and its RES/EDGE handlers are generic 4-step stubs with no per-check logic. The 7 RES-RT cases exist as specifications in `skills/dev-testing/references/roundtable-tests.md` (RES-RT-001..007), still listed there under "Pending (QUAL-001 Priority 2)". Fully implemented today: ENV-* (7 checks) and VAL-RT-* (5 checks).

## 2. TEST-003 — session resilience

**Verdict: all four open tasks still open.** The item's own 2026-06-13 location-correction note is accurate; this pass confirms it and adds detail.

- **State-transition checks: absent.** `agents/validation/session-qa.md` implements exactly STR-001..006 (`:67-417`), STRAT-D1/D2 (`:423-503`, debate only), DIAG-001..003 (`:509-699`, diagnostic mode only). The nearest thing is **STR-002 "Artifact States Valid"** (`:116`), which validates that a state *value* is legal for its artifact type — **state membership, not state transitions**. Nothing checks round/session lifecycle transitions or detects an interrupted round. `EXEC-*` is an explicit "Future" section (owned by QUAL-002).
- **CTX-\*: defined, unimplemented**, exactly like RES-RT-*. Definitions in `roundtable-tests.md` and `check-registry.md`; `dev-validator.md` accepts no `CTX` category.
- **Live doc/code contradiction**: `check-registry.md:55` and `:166` both document the invocation `/s2s:dev:test --context`. **That flag does not exist** — zero hits in `commands/dev/test.md`, whose argument hint is `[--validate] [--resume] [--edge] [--all] [--session <path>] [--cleanup]`. A contributor following the reference hits a phantom flag.
- **Mid-write recovery: absent.** `skills/roundtable-execution/references/error-handling.md` is **54 lines** total. It has fail-fast on write failure ("STOP immediately… do NOT continue without persistence"), round-level partial recovery at participant granularity, and corruption *detection* ("report corruption error with line number"). It has no mid-write protocol: no atomic write (temp + rename), no backup-before-write, and — the concrete hole — **no reconciliation when `.s2s/state.json` and the session YAML disagree**. Those two are written by separate Write calls (`commands/roundtable.md`, `phase-2-core.md`), so a crash between them leaves them divergent with nothing in the codebase able to repair or even notice it.
- **E2e resume tests: now unblocked.** The procedure that did not exist when TEST-003 was written now ships: `skills/dev-testing/references/dogfood-e2e.md` (TECH-014, v0.8.0), with the manual interruption steps in `roundtable-tests.md`. The task changed shape: from "invent a procedure" to "execute the runbook".

**Cross-cutting**: QUAL-001's RES-RT-* task and TEST-003's CTX-* task are **the same edit** — the `categories` enum and the RES/EDGE stubs in `agents/dev/dev-validator.md`. They are blocked on each other only in the sense that doing one without the other wastes the trip. Do them together.

## 3. BUG-008 — init and .gitignore

**Verdict: premise narrowed, not resolved.** "Never touches `.gitignore`" is now false — `commands/init.md:603-619` (§5.4b, shipped with TECH-013) appends `.s2s/local/`, idempotently, creating the file if absent. But that block is **privacy-only**. Artifact hygiene was never addressed, and the item's proposed block is stale: it predates `state.json`, `context-window.json`, `qa/`, the caches and `.s2s/local/` itself.

Transient artifacts left unignored, with their writers:

| Path | Written by |
|------|------------|
| `.s2s/state.json` | `commands/roundtable.md`, `skills/roundtable-execution/references/phase-2-core.md` |
| `.s2s/sessions/**` (session YAML, context/config snapshots, `rounds/*.yaml` verbose dumps, `*-summary.md`) | `commands/roundtable.md`, `skills/output-generation/SKILL.md` |

| `.s2s/qa/evidence/*.yaml` | `agents/validation/session-qa.md`, `commands/session/validate.md` |

Tracked by design and not to be ignored: `config.yaml`, `CONTEXT.md`, `README.md`, `BACKLOG.md`, `ideas.md`, `workspace.yaml`, `requirements.md`, `architecture.md`, `decisions/`, `plans/`.

Note that the intent was already **documented and unenforced**: `skills/s2s-guide/references/workspace.md` lists `sessions/` under "Never Version (add to .gitignore)". Nothing acted on it.

The corrected block (denylist, in the backlog item) is preferred over the allowlist form the spec2ship repo uses on itself: in a user project an allowlist is fragile, because every new tracked artifact type needs a new `!` line and a forgotten one silently vanishes from git.

## Method note (worth keeping)

The two false claims (QUAL-001's exclusion, BUG-008's "never touches") had one thing in common: **both were true when written and were invalidated by later work that nobody propagated back**. QUAL-001's exclusion was presumably aspirational from the start; BUG-008's premise was silently half-fixed by TECH-013, whose author was solving a privacy problem and had no reason to look at an artifact-hygiene ticket.

The cheap countermeasure is the one applied here: before planning a cycle, re-verify the items you intend to plan **against the code**, not against their own text — and record the evidence, so the verification is not repeated from zero next time. FEAT-010 ("cross-validate backlog status with git history") is the automated version of this pass and remains a reasonable idea, though it would have caught neither of these two: both items had the *right* status, and the *wrong* body.
