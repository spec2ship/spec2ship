## 3. The 4 PHASE 1 variants and the canonical profile-driven skeleton

### 3.1 Empirical confirmation (master path)

Inspected 3 Phase 4 master-path dogfood session files:

| Worktree | Run | `workflow_type` in session file | Session dir contents |
|----------|-----|--------------------------------|----------------------|
| exp52 | `/s2s:roundtable --workflow-type design` | `"design"` ✓ correct | **empty** (no snapshots, no `rounds/`) |
| exp49 | `/s2s:roundtable --workflow-type specs` | `"specs"` ✓ correct | `rounds/` only (**no snapshot files**) |
| exp51 | `/s2s:roundtable --workflow-type brainstorm` | `"brainstorm"` ✓ correct | `rounds/` only (**no snapshot files**) |

Two facts confirmed:
1. **The `workflow_type` literal at roundtable.md:260 is "soft-broken"**: the executing LLM substitutes the correct value by inference. It works today but is a correctness liability and must be parametrized.
2. **The master creates NO snapshot files**, even when running specs/design/brainstorm via `--workflow-type`. The session directory holds at most `rounds/`. The direct commands create `config-snapshot.yaml` + `context-snapshot.yaml` + `agenda.yaml`. This is the round-1 finding, now empirically proven.

Master-path specs/design ran with explicit CLI topics (exp49 "Acceptance criteria for the Gift Storm finale", exp52 "Compare React vs Vue..."). The direct commands instead synthesize the topic from the profile (`specs.yaml topic.pattern: "Requirements definition for {project_name}"`). **The master ignored `PROFILE.topic.source`.** Phase 8 thin `/s2s:specs` and `/s2s:design` pass no topic, so the generalized PHASE 1 MUST synthesize per profile. §8.5 must test the no-topic path (Phase 4 §4.5 never did).

| Variable | Set by | Mandatory | Master consumes at |

Strategy and default output-type are NOT passed: the master resolves strategy via the D3 hierarchy (`CLI → config.yaml → profile.default_strategy`, with `strategy_constraints.forced` overriding) and output-type from `workflow_type` (roundtable.md:463-470 dispatch table).

`--focus` decision (audit step 5): `--focus` is parsed in current design.md but lightly used; preserve behavior by carrying `FOCUS_AREA` as a facilitator discussion-context hint (matching today). Full wiring is a §8.3 detail, not a behavior change.

## 7. Smart Source Detection placement (decision)

specs.md keep-blocks sum to ~162 lines with Smart Source Detection (~66 lines) **inline**. Extracting it to `roundtable-execution/references/specs-source-detection.md` would land specs.md at ~100 but adds a new skill file and a Read indirection.

**Decision: keep Smart Source Detection inline.** ~162 is within the ≤180 budget; Phase 8 stays a pure command-layer refactor with no new skill file. Extraction is recorded as a post-v0.4.0 optional optimization (parent plan §8).
