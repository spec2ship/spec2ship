## Non-blocking findings (post-v0.5.0 follow-up candidates)

- **F1 — `assign_debate_sides` launcher pre-step vestigial for design+debate**: reported by post-fix design run (exp58 step 2). The hook is now driven by per-round `facilitator_emergent` policy; the launcher's static side assignment is dead code.
- **F2 — token-tracker recap math glitch after resume**: post-compact resume init worked (BUG-012 PASS), but the round-3 recap reported `statusline returned 0%` and negative deltas because the per-round T1/T2/T3 capture markers were not reset for the new round. Model self-described as "non-blocking" and continued. Likely an instruction-level oversight on resume init not clearing the previous round's capture state.
- **F3 — token-tracker cache loses workflow params after compact**: post-resume cache shows `workflowType=`, `strategy=`, `phase=`, `participantsCount=` empty because the model called `token-tracker.sh init` with only `session-id` + `round-number` (optional positional params dropped). Statusline display loses RT context.
- **F4 — pre-fix Phase 3 cleanup incomplete on forced conclude**: pre-fix exp63 wrote `requirements.md` in response to "Conclude now anyway" but did not close the session (`status: "active"` left intact, `closed_at: null`, no `state.json` clear). Pre-v0.5.0 quirk, no longer reachable post-fix because §2.9b would override `next` before reaching output. Historical only.
- **F5 — pre-fix "Conclude now anyway" not actually concluding**: pre-fix exp63 repeatedly continued to the next round despite user selecting option 3 at round 3, 4, and 5. The user choice was treated as "save snapshot + continue" rather than "stop". Pre-v0.5.0 quirk; post-fix path goes through §2.9c confirmation which dispatches via §2.9d as designed. Historical only.

F1–F3 are post-v0.5.0 candidates. F4–F5 are pre-fix archaeology, not actionable.
